    **Modular Permissions System:**

    1. Create `app/Permissions/PermissionsProvider.php` interface:
    ```php
    interface PermissionsProvider
    {
        /** Return flat array of permission strings, e.g. ['charts:view:own', 'charts:view:all'] */
        public function permissions(): array;

        /** Return array keyed by Role enum value, each value is array of permission strings for that role.
         *  Use ['*'] to grant all permissions from permissions(). */
        public function roles(): array;
    }
    ```

    2. Create `app/Permissions/PermissionsRegistrar.php`:
    - Property: `private array $providers = []`
    - Method `register(string $providerClass): self` -- adds class-string to providers list, returns self for chaining
    - Method `boot(): void` -- instantiates each provider, collects all permissions, merges role arrays per role, then calls `Jetstream::role()` once per role with the merged permission set and descriptions. Must handle the wildcard `['*']` convention by expanding to all permissions from that provider.
    - The boot method should also call `Jetstream::permissions()` with all collected permissions.
    - Use explicit registration (not auto-discovery) per research pitfall #7. Providers are registered in JetstreamServiceProvider.

    3. Create `app/Permissions/CorePermissions.php` implementing `PermissionsProvider`:
    - Extract ALL existing permissions from the current `configurePermissions()` method in JetstreamServiceProvider
    - Copy the existing role-to-permission mapping exactly. Do NOT change any existing permission behavior.
    - This is a refactor -- existing functionality must be identical after this change.

    4. Create `app/Permissions/NotificationPermissions.php` implementing `PermissionsProvider`:
    - Permissions: `['notifications:view:own', 'notification-preferences:manage:own']`
    - Roles: all roles (Owner, Admin, Manager, Employee) get both permissions (every user manages their own)

    5. Refactor `JetstreamServiceProvider::configurePermissions()`:
    - Replace the entire monolithic permission/role definition with:
      ```php
      $registrar = new PermissionsRegistrar();
      $registrar
          ->register(CorePermissions::class)
          ->register(NotificationPermissions::class);
      $registrar->boot();
      ```
    - Remove all inline `Jetstream::role()` and `Jetstream::permissions()` calls
    - The notification permissions were added in Plan 01-01 directly to the monolithic method; this refactors them into their own file

    **Verification of permissions refactor:**
