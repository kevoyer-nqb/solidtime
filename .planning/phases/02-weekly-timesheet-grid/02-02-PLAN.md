**TimesheetGridCell.vue** (`resources/js/Components/TimesheetGrid/TimesheetGridCell.vue`):
- Props: `cell: TimesheetGridCell`, `projectId: string | null`, `taskId: string | null`, `date: string`
- State:
  - `isEditing = ref(false)` -- whether the cell is in edit mode
  - `editValue = ref('')` -- the text input value during editing
  - `isSaving = ref(false)` -- loading state during save
- Display mode (not editing):
  - If `cell.total_seconds > 0`: show formatted duration using `formatHumanReadableDuration(cell.total_seconds)`
  - If `cell.total_seconds === 0` and `cell.time_entry_ids.length === 0`: show empty state (blank or a subtle "+" icon on hover)
  - If multiple entries: show a small badge/indicator like "(2)" next to the duration to signal multiple entries underlie this cell
  - Make the cell clickable to enter edit mode
  - Cursor: `cursor-pointer` for filled cells, `cursor-cell` for empty cells
- Edit mode:
  - Replace display with an `<input type="text">` that is auto-focused
  - Pre-fill input with the current formatted duration (for existing entries) or empty string (for new entries)
  - Input classes: `w-full text-center bg-transparent border-0 border-b-2 border-blue-500 focus:ring-0 text-sm p-1` (minimal inline style)
  - On Enter or blur: parse the input with `parseTimeInput(editValue.value)` from `@/packages/ui/src/utils/time.ts`
  - On Escape: cancel editing, revert to display mode without saving
- Save logic (on Enter or blur with changed value):
  - If cell has entries (`cell.time_entry_ids.length > 0`):
    - Call `useTimesheetGridStore().updateCellDuration(cell.time_entry_ids, parsedSeconds, cell.total_seconds)`
    - This adjusts the last entry to match the new total (multi-entry logic handled in store)
  - If cell is empty (`cell.time_entry_ids.length === 0`) and parsedSeconds > 0:
    - Call `useTimesheetGridStore().createCellEntry(projectId, taskId, date, parsedSeconds)`
    - This creates a new time entry with synthesized start/end
  - If parsedSeconds is 0 or NaN or null: cancel editing (do not create zero-duration entries)
  - Set `isSaving = true` during the API call, show a subtle spinner or opacity change
  - After save completes: exit edit mode, grid data will refresh via TanStack Query invalidation
- Error handling: if parseTimeInput returns null/NaN, show a brief red flash on the cell border and revert to display mode
- Template ref on input element for auto-focus: `const inputRef = ref<HTMLInputElement | null>(null)` with `onMounted(() => inputRef.value?.select())`
- Use `watch(isEditing, ...)` or `nextTick` to focus the input when entering edit mode

**Duration parsing**: Import `parseTimeInput` from `@/packages/ui/src/utils/time.ts`. This handles all formats: "1h 30m", "1:30", "90" (minutes), "1.5" (decimal hours). Do NOT write a custom parser.

**IMPORTANT multi-entry cell editing**: When a cell has multiple entries (time_entry_ids.length > 1), the cell shows the aggregate duration. Editing changes the LAST entry's duration to make the total match the new value. The store's `updateCellDuration` method handles this. The cell UI should show a small indicator (e.g., a tiny number badge) when multiple entries exist, so the user knows the cell aggregates multiple entries.

**IMPORTANT**: Tab key navigation between cells is a nice-to-have but NOT required for this task. Focus on Enter/Escape/blur behavior first.
