Create the backend API endpoint that returns time entry data structured for grid rendering.

**TimesheetGridIndexRequest** (`app/Http/Requests/V1/TimesheetGrid/TimesheetGridIndexRequest.php`):
- Extend BaseFormRequest (follow existing pattern from TimeEntryStoreRequest)
- Single optional field: `date` (string, nullable, format `Y-m-d`, defaults to today)
- No authorization logic in request (handled by controller)

**TimesheetGridService** (`app/Service/TimesheetGridService.php`):
- Stateless service class following existing service patterns (DailyTimeSummaryService)
- Method: `buildGridData(Organization $organization, Member $member, Carbon $date, DateBoundaryService $dateBoundaryService): array`
- Query TimeEntry directly (NOT DailyTimeSummary) to avoid staleness -- per research recommendation
- Filter: `organization_id`, `member_id`, `start >= weekBoundariesUtc['start']`, `end <= weekBoundariesUtc['end']`, `whereNotNull('end')` (exclude running entries)
- Use `$dateBoundaryService->getWeekDates($date, $timezone, $weekStartDay)` to get the 7 local dates
- Use `$dateBoundaryService->getWeekBoundariesUtc($date, $timezone, $weekStartDay)` for the UTC query range
- Get timezone from `$organization->getEffectiveTimezone()` and week start from `$organization->week_start_day`
- Eager load `project:id,name,color,is_billable` and `task:id,name` relationships
- Group entries by `project_id|task_id` composite key
- For each group (row), assign entries to their local date by converting entry start to org timezone: `Carbon::parse($entry->start)->setTimezone($timezone)->format('Y-m-d')`
- Build response structure matching the TypeScript interfaces in 02-RESEARCH.md:
  - `week_start`, `week_end`: ISO date strings
  - `days`: array of 7 ISO date strings
  - `rows`: array of objects with `project_id`, `project_name`, `project_color`, `task_id`, `task_name`, `cells` (7 cells with `date`, `total_seconds`, `time_entry_ids`), `row_total`
  - `daily_totals`: array of 7 numbers (sum of all rows per day)
  - `weekly_total`: sum of all daily totals
- Calculate duration for each entry using the existing `getDuration()` accessor on TimeEntry model (returns seconds)

**TimesheetGridController** (`app/Http/Controllers/Api/V1/TimesheetGridController.php`):
- Extend `App\Http\Controllers\Api\V1\Controller` (base controller)
- Single method: `index(Organization $organization, TimesheetGridIndexRequest $request, DateBoundaryService $dateBoundaryService)`
- Permission check: `$this->checkPermission($organization, 'time-entries:view:own')` (reuse existing permission)
- Get current member via `$this->member($organization)` (base controller method)
- Parse date from request or default to `Carbon::now()`
- Inject TimesheetGridService and call buildGridData
- Return `response()->json(['data' => $gridData])`

**TimesheetGridResource** (`app/Http/Resources/V1/TimesheetGrid/TimesheetGridResource.php`):
- Simple resource class for potential future use; for now the controller returns raw JSON since the data structure is custom (not a model-based resource)
- Create as a placeholder following existing Resource patterns

**IMPORTANT timezone handling**: When assigning entries to days, use the organization timezone, NOT UTC. An entry at 11pm EST Monday must appear in Monday's column, not Tuesday's (UTC). The DateBoundaryService handles this correctly via getWeekDates() which returns local dates.

**IMPORTANT**: Do NOT use DailyTimeSummary table. Query TimeEntry directly for freshness. Single member + single week is at most ~50 entries, well within performance limits.

**useTimesheetGrid.ts** (`resources/js/utils/useTimesheetGrid.ts`):
- Follow the existing store pattern from `useTimeEntries.ts` and the TanStack Query pattern from `Calendar.vue`
- Create Pinia store: `export const useTimesheetGridStore = defineStore('timesheetGrid', () => { ... })`
- State:
  - `currentWeekDate = ref<string>(dayjs().format('YYYY-MM-DD'))` -- the anchor date for the current week view
- Week navigation methods:
  - `goToPreviousWeek()`: subtract 7 days from currentWeekDate
  - `goToNextWeek()`: add 7 days to currentWeekDate
  - `goToCurrentWeek()`: set to today's date
- Data fetching (TanStack Query):
  - Export a composable `useTimesheetGridQuery()` that returns `useQuery` with:
    - `queryKey: ['timesheet-grid', computed(() => getCurrentOrganizationId()), currentWeekDate]`
    - `queryFn`: fetch from `/api/v1/organizations/${orgId}/timesheet-grid?date=${currentWeekDate.value}`
    - Use direct fetch with X-XSRF-TOKEN header (Phase 1 pattern from useNotificationBell.ts -- NOT the Zodios client)
    - Extract XSRF token from document.cookie: `document.cookie.split('; ').find(c => c.startsWith('XSRF-TOKEN='))?.split('=')[1]`
    - Must decode the cookie value with `decodeURIComponent()` before using as header
    - Include `credentials: 'same-origin'` in fetch options
    - `enabled: computed(() => !!getCurrentOrganizationId())`
  - Grid invalidation method: `invalidateGrid()` calls `queryClient.invalidateQueries({ queryKey: ['timesheet-grid'] })`
- Cell update method: `async updateCellDuration(timeEntryIds: string[], newTotalSeconds: number, currentTotalSeconds: number)`
  - If single entry: call existing `api.updateTimeEntry` to set new duration (adjust end = start + newTotalSeconds)
  - If multiple entries: adjust last entry's duration by the delta (newTotalSeconds - currentTotalSeconds + lastEntryDuration)
  - After success: call `invalidateGrid()`
  - Wrap in `handleApiRequestNotifications()` from useNotificationsStore
- Cell create method: `async createCellEntry(projectId: string | null, taskId: string | null, date: string, durationSeconds: number)`
  - Synthesize start time: `dayjs.tz(date + ' 09:00:00', getUserTimezone()).utc().format('YYYY-MM-DDTHH:mm:ss[Z]')`
  - Synthesize end time: start + durationSeconds
  - Set `billable` to project's `is_billable` if project is set, false otherwise (per research recommendation)
  - Call existing `api.createTimeEntry` with the synthesized data
  - After success: call `invalidateGrid()`
  - Wrap in `handleApiRequestNotifications()` from useNotificationsStore
- Type definitions at the top of the file (or in a separate types file if preferred):
  ```typescript
  interface TimesheetGridResponse {
    week_start: string;
    week_end: string;
    days: string[];
    rows: TimesheetGridRow[];
    daily_totals: number[];
    weekly_total: number;
  }
  interface TimesheetGridRow {
    project_id: string | null;
    project_name: string;
    project_color: string;
    task_id: string | null;
    task_name: string | null;
    cells: TimesheetGridCell[];
    row_total: number;
  }
  interface TimesheetGridCell {
    date: string;
    total_seconds: number;
    time_entry_ids: string[];
  }
  ```
- Return from store: `currentWeekDate`, `goToPreviousWeek`, `goToNextWeek`, `goToCurrentWeek`, `invalidateGrid`, `updateCellDuration`, `createCellEntry`
- Export the query composable separately: `useTimesheetGridQuery`
